# Керування AI під час роботи

Інструмент: **Claude Desktop (вкладка Code)**, модель Claude Opus. Розподіл ролей: AI пише код і проводить перевірки; постановка задач, рішення та приймання результату — за людиною.

## Процес

1. **Спочатку аналіз, потім код.** Перший запит: «Уважно вивчи вимоги та запропонуй план». AI прочитав документацію API і зробив ~25 живих запитів, щоб перевірити реальну поведінку, а не лише опис. Вже на цьому етапі знайшлися обмеження (одна ніша на запит, дані відстають на ~4 тижні, `dr: null`).
2. **Рішення — за людиною.** AI запропонував PHP/Laravel під стек вакансії. Остаточний вибір — JS + Netlify, плюс дві додаткові вимоги: пошук інструментів за задачею (музика, відео, лого, фавіконки, апскейл, ретуш…) і фільтр «платно / безкоштовно / потрібна реєстрація». Перед реалізацією AI перевірив, чи вистачає на це даних API: таксономію задач і сигнали ціни на вибірці з 40 сайтів.
3. **Правила проєкту** зафіксовані в `CLAUDE.md`: стек, «не вигадувати поля API», чесні позначки, обидві мови, токени дизайну.
4. **Дизайн за референсом.** AI витягнув палітру з framerbuilder.framer.website (computed styles + скріншоти): фон `#161616`, поверхні `#1c1c1c`, акцент `#0099ff`, білі pill-кнопки. Шрифт Inter і радіус 100px — вимоги з постановки задачі.
5. **Перевірка в браузері після кожного етапу**: головна, фільтри, картка сайту, порівняння, `/en/`, мобільна ширина 375px.

## Де AI помилявся і як це виловили

| Проблема | Як помітили | Виправлення |
|---|---|---|
| Документація обіцяє відкритий CORS, і AI спершу зробив прямі запити з браузера | Фільтр у браузері показав «FreeSerp не відповідає»; у консолі — `Access-Control-Allow-Origin: '*, *'` | Проксі `/api/fs` через Netlify rewrite |
| `ai_startups=1` для задач відсікав медійні ніші | Порівняння кількості результатів (353 → 154 для Audio & Music) | Для задач і ніш — лише `ai_categories` |
| Задача «фавіконки» через `category=ai` давала SEO-сервіси | Огляд топ-результатів | `q=favicon generator`, сортування за релевантністю |
| Блокування за `category=betting/casino` ховало favicon.io | Картка favicon.io показала «немає в індексі», хоча API його повертає | Блокування лише за текстом |
| Посилання «Pricing» у меню давало «Платно» freemium-сервісам | Ручна перевірка 24 відомих сервісів | «Pricing» — слабка ознака, лише підтверджує інші |
| Невидимі підказки бейджів розширювали сторінку на мобільному (449px при ширині 375px) | `scrollWidth` у мобільній емуляції | `display: none` замість `opacity: 0` |
| Темні фавіконки зливалися з темним фоном | Скріншот картки | Світла підкладка, як у референсі |
| У нішах зображень траплялися NSFW-сайти (undress/nudify) | Вибірка з `content=1` | Стоп-лист |
| Підказки на «su» не знаходили suno.com | Ручна перевірка підказок; запити `su`, `su*` до API | API шукає лише цілі слова → локальний індекс сайтів для префіксного пошуку |
| Стоп-лист пропускав `sexhd88.live` (без межі слова після «sex») | Підказки без вибраної ніші | `sex\w*` |
| Підказки без ніші показували не-AI сайти | Скріншот підказок на «муз» | Без ніші — обмеження `category=ai` |
| `nudeai.com` пройшов стоп-лист і потрапив на сторінку «3D» та в sitemap (`\bnude\b` не ловить «nude» всередині домену) | Окремий аудит: прогін стоп-листа по всіх ~1000 сайтах зі збірки | Однозначні слова (`nude`, `porn`, `nsfw`…) шукаються як підрядок; перевірено, що нових хибних блокувань немає |
| Випадний список відкривався знову одразу після вибору | Клік мишею в браузері (синтетичний `click()` цього не показував) | Список лежить усередині `<label>`, і клік пересилався кнопці → `preventDefault` |
| «Усі ніші» на сторінці задачі показували google.com і 17 млн сайтів | Аудит усіх фільтрів запитами до API | Розширення до `ai_startups=1` + ключове слово задачі |
| Проксі `/api/fs` пропускав будь-які параметри | `curl /api/fs?index=web…` на задеплоєному сайті | Netlify Function зі списком дозволених параметрів |
| Домен, якого немає в індексі, «застрягав» у порівнянні невидимим і займав слот | Ручний прогін сценарію `?d=a,b,c` | Такі домени прибираються зі списку після перевірки |
| Збірка без API задеплоїла б порожній сайт | Симуляція збою мережі під час збірки | Збірка падає, Netlify лишає попередню версію |
| Після деплою браузер міг поєднати старі й нові модулі (кеш 1 год без версії) | Аудит заголовків кешу | `/assets/<hash>/` + `immutable` |
| Шапка на телефоні займала два рядки, «Порівняння» ховалося за краєм | Скріншот на 375px | Бургер-меню |

**Повторний аудит (4 жовтня, вечір).** Окремий запит до AI: «уважно пройди кожне флоу і знайди вразливості». Перевірка — запити на задеплоєний сайт, прогін у браузері (десктоп і 375px), імітація збою мережі, звірка з даними API.

| Проблема | Як помітили | Виправлення |
|---|---|---|
| Проксі падав на `?__proto__=1` (502 зі стек-трейсом), `?constructor=1` проходив список дозволених | curl на задеплоєний сайт | `Object.hasOwn`, try/catch, відповідь завжди JSON із CSP |
| Проксі віддавав HTML-сторінку помилки FreeSerp з нашого домену й кешував будь-яку 2xx | Запит з неможливою датою (`2026-02-31` → 502 у FreeSerp) | Дати перевіряються як справжні; кешуються лише валідні відповіді |
| Немає ліміту запитів до проксі | Аналіз вартості: 1 запит = до 465 КБ, унікальний `q` минає кеш | `rateLimit` 60/хв з IP; 429 у браузері — окреме повідомлення без повтору |
| «Домен виявлено: 1 січ. 2025» на 85% карток | Підрахунок значень у зібраних сторінках | Це дата старту відстеження → «до 2025 р.» |
| Esc у пошуку не лише закривав підказки, а й стирав запит | Клавіатурний прогін у браузері | `preventDefault`, поки відкриті підказки |
| На телефоні фавіконки й бейджі карток перекривали відкритий список фільтра | Скріншот 375px | Панель фільтрів лишається positioned, тож її z-index працює |
| Збій API на сторінці порівняння: «невидимий» домен займав слот, а повідомлення казало «немає в індексі» | Імітація збою мережі (підміна `fetch`) | Колонка «Дані не завантажилися» з повтором; помилка мережі й «немає в індексі» розрізняються |
| З фільтром ціни сортування за DR/датою ламалося на межі двох злитих запитів | Перевірка порядку на всіх сторінках видачі | Злитий список пересортовується |
| Чипи 14 ніш вели на каталог без фільтра | Звірка категорій зі збірки зі списком фільтра | +16 ніш; будь-яка коректна ніша з URL працює як фільтр |
| Двійники брендів (midjourney.online, chatgptxt.com) першими в пошуку, а оригіналів в індексі немає | Запити до API за назвами брендів | Позначка «Не офіційний сайт X» з поясненням |
| Агентства, портфоліо й особисті сторінки в «Нових стартапах» | Ручний огляд 159 сайтів із блоків «нове» | Фільтр за описом сайту; правило вивірене на 2 018 сайтах, одне хибне спрацювання прибрано до релізу |

**Третій аудит (4 жовтня, ніч).** Той самий запит «пройди кожне флоу», плюс прогін евристик на живих даних API (428 сайтів із текстом сторінок, 1 129 — для стоп-листа). Кожне правило перед змінами перевірялося на вибірці, після — порівнянням «було / стало».

## Що не приймалося від AI без перевірки
- Твердження документації (CORS, таксономія) — усе перевірялося запитами.
- Точність евристики ціни — перевірена вручну на 24 сервісах, результат описаний чесно (`docs/API_NOTES.md`).
- Вигляд — кожен екран перевірявся на скріншоті, а не «має бути гаразд».
