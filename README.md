# AI Radar — AI-інструмент для будь-якої задачі

**Демо:** https://ai-radar-tech.netlify.app/ · **Мови:** українська (за замовчуванням) і англійська (`/en/`)

Тестове завдання Semalt. Веб-проєкт на публічному [FreeSerp API](https://freeserp.ai/docs.php) (`index=sites`, головні сторінки, ніша AI).

**Ідея:** основа — пошук AI-інструменту під конкретну задачу (музика, відео, лого, фавіконки, ретуш…) з позначками «безкоштовно / платно / без реєстрації». Фіча — у кожній категорії видно найновіші AI-стартапи, які щойно з’явилися в індексі.

План сайту (мета, аудиторія, сторінки, структура) — внутрішній документ [`docs/PLAN.md`](docs/PLAN.md), на клієнтському сайті не публікується.

## Що зроблено

- **Нові стартапи в категорії (фіча):** блок «Нове в категорії» на кожній сторінці задачі й ніші (останні появи за 30 днів даних, для малих категорій — найсвіжіші загалом), вкладки «Нові стартапи за категоріями» на головній, бейдж «Новий» (останні 14 днів даних) на картках, сторінка «Нові стартапи» з вибором ніші.
- **Пошук інструментів за задачею** — 21 задача: музика, аудіо, озвучка, клонування голосу, транскрибація, генерація й монтаж відео, генерація зображень, покращення якості (апскейл), ретуш, видалення фону, лого, брендинг, фавіконки, іконки, аватари, 3D, UI-дизайн, копірайтинг, переклад, інтер’єр.
- **Фільтри ціни та доступу:** Free / freemium, Безкоштовно, Freemium, Пробний період, Платно; Без реєстрації, Є акаунти, Лист очікування; плюс «Є API» та «Open source». В API таких полів немає, тож їх визначає евристика за текстом головної сторінки. **Біля кожної позначки є підказка «чому так»** із фразами, що спрацювали (її зачитують і скрінрідери). Слабкі ознаки («Pricing», «premium», «subscribe») самі по собі не роблять сайт платним, «$0» і «feel free» не вважаються ціною, суми на кшталт «$10M» (інвестиції) — теж; «free 7-day trial» — це пробний період, а не безкоштовний тариф, «API keys» (ключ користувача) — не ознака власного API.
- **«Ніша» — перший фільтр у кожній формі** (каталог, задачі, ніші, новинки, пошук на головній, порівняння). На сторінці задачі за замовчуванням стоїть ніша задачі, її можна змінити або скинути.
- **Підказки в усіх полях пошуку:** задачі та ніші (локально, обома мовами) і сайти. API шукає лише цілі слова, тому відомі сайти підказуються за префіксом із локального індексу (будується під час збірки), а результати API додаються після них. Якщо збіг знайдено англійською назвою, вона показана під українською («su» → «Транскрибація і субтитри» / Transcription & subtitles). Керування стрілками, Enter, Esc.
- **Запити українською:** API шукає лише англійський текст сторінок («генератор лого» → 0 результатів), тому пошук на головній спершу зіставляє запит із задачами й нішами за словниками основ (`src/js/query.js`): «генератор лого» відкриває задачу «Логотипи», «чат-бот» — нішу чат-ботів, «video editor» — «Монтаж відео». Якщо кириличний запит усе ж дійшов до каталогу й нічого не знайшов, сайт пояснює, що шукати треба англійською.
- **Пошук за назвою чи доменом:** у каталозі введений запит шукає серед усіх AI-сайтів (`category=ai`), а не лише серед «стартапів» (`ai_startups=1` не містить suno.com, тому за запитом «suno» першими виходили двійники). Якщо запит — домен, сайт шукається окремо й показується над результатами (elevenlabs.io в API взагалі без категорії AI).
- **Каталог AI-стартапів:** пошук, ніша (61 категорія; будь-яка інша ніша з API теж працює як фільтр), конструктор (Lovable, v0, Bolt, Base44, «будь-який AI-конструктор», Next.js, WordPress…), домен (.ai, .io…), діапазон DR, дати появи, сортування. Стан фільтрів зберігається в URL, тому посиланням можна поділитися.
- **15 SEO-сторінок ніш**, **«Нові стартапи»** (останній тиждень наявних даних, ніша — перший фільтр), **«Усі AI-сайти»** (загальний список), **картка сайту** з фактами та схожими сайтами, **порівняння до 3 сайтів** (плаваюча панель, посилання `?d=a,b,c`).
- **Головна в два кроки:** пошук (ніша + запит + підказки; назва задачі веде одразу на її сторінку) і плитки задач → «Нові стартапи за категоріями». Лічильники — про користь: AI-стартапів у базі, нових за тиждень, задач, ніш.
- **SEO:** під час збірки генеруються ~1 560 статичних сторінок (задачі, ніші, новинки, картки ~740 сайтів × 2 мови); title/description, canonical, hreflang, JSON-LD, sitemap.xml, robots.txt, картинка для превью посилань (og:image 1200×630, окремо для uk і en, у стилі сайту). Фільтри працюють у браузері поверх цих сторінок тими самими шаблонами.
- **Якість даних:**
  - Стоп-лист NSFW, казино та «мертвих» доменів (зокрема коли слово «приклеєне» до домену: `nudeai.com`). Сервіси модерації й захисту дітей, які описують боротьбу з таким вмістом (telegram-bot.app, safer.io), лишаються; перевірено на 1 129 сайтах — жоден генератор NSFW не повернувся.
  - Біля «Показано 1–24 з N» сказано, скільки сайтів на сторінці приховано і чому, — раніше їх просто не було в сітці.
  - Агентства, консалтинг, портфоліо й особисті сторінки не потрапляють у списки. Їх визначає опис сайту від API («X is a … agency», «the personal website of…»); правило перевірене на 2 018 сайтах з індексу. Картка й порівняння такі домени все одно відкривають.
  - Сайти з назвою відомого бренду не на його офіційному домені (`chatgptxt.com` «Chat GPT login», `midjourney.online`, CapCut MOD APK) отримують позначку «Не офіційний сайт X» з поясненням. Без неї такі двійники виходили першими в пошуку за назвою бренду. Для назв, які є звичайними словами чи іменами (Claude, Grok, Perplexity…), потрібен ще й AI-контекст в описі: винна крамниця claude-leblanc.com позначку більше не отримує.
  - `first_seen = 2025-01-01` — це дата старту відстеження в FreeSerp (так у ~85% сайтів, навіть у google.com), тож у картці пишемо «до 2025 р.».
  - Кеш оброблених відповідей (sessionStorage, 10 хв), повтор при помилці, стани «порожньо / помилка / забагато запитів».
- **Безпека та надійність:**
  - Проксі `/api/fs` — Netlify Function зі списком дозволених параметрів, а не голий rewrite. Інакше домен сайту працював би як відкритий ретранслятор FreeSerp з будь-якими параметрами (`index=web`, чужий `agent`…). Ключі перевіряються як власні властивості списку (`?__proto__=` раніше валив функцію зі стек-трейсом), дати — як справжні календарні (на `2026-02-31` FreeSerp відповідає 502).
  - Проксі завжди відповідає JSON із `Content-Security-Policy: default-src 'none'`, навіть коли FreeSerp віддає HTML-сторінку помилки; у CDN кешуються лише справжні відповіді.
  - Проксі сам класифікує текст сторінки (той самий `classify.js`) і віддає лише вердикт: відповідь на 100 сайтів важить ~100 КБ замість ~450 КБ, а сирий текст сторінок через наш домен не ретранслюється.
  - Перемикач мови не можна перетворити на посилання на чужий сайт (`/en//evil.com` раніше давав `//evil.com`) і тепер зберігає поточні фільтри та список порівняння.
  - Ліміт 60 запитів на хвилину з однієї IP-адреси (`rateLimit` Netlify, працює на всіх тарифах): скрипт не вичерпає квоту функцій і не підставить під обмеження спільний `agent` у FreeSerp. Браузер на 429 показує «Забагато запитів» і не повторює запит.
  - Заголовки: Content-Security-Policy (inline-скрипт дозволено лише за хешем), `X-Frame-Options: DENY`, `Permissions-Policy`, `nosniff`. Фавіконки Google завантажуються без Referer.
  - Якщо API недоступний або повернув порожні дані, збірка падає, і Netlify лишає попередню робочу версію замість порожнього сайту.
  - JS/CSS лежать у теці з хешем вмісту (`/assets/<hash>/`): після деплою браузер не може змішати старі й нові модулі, тож їх можна кешувати назавжди.
  - Локальний сервер не падає від «битих» URL на кшталт `/%E0%A4%A` і слухає лише 127.0.0.1.
- **Дизайн:** темна тема за референсом framerbuilder.framer.website, Inter, кнопки та інпути зі скругленням 100px, власні випадні списки замість системних (клавіатура, ARIA listbox, пошук за першими літерами), адаптивна верстка з бургер-меню на телефоні (перевірено на 375 і 320px).

### Робота з AI
Робота велася в Claude Desktop (Code): AI пише код і проводить перевірки, постановка задач, рішення та приймання — за людиною. Правила для AI — у [`CLAUDE.md`](CLAUDE.md). Процес, три аудити та помилки, які вдалося виловити (дубльований CORS-заголовок API, відкритий ретранслятор на проксі, кириличні запити, яких API не знаходить): [`docs/AI_LOG.md`](docs/AI_LOG.md).

Фінальну перевірку проведено вручну, без AI, за чек-листом: демо в режимі інкогніто й з іншої мережі, Network і Console, кожен фільтр і крайові випадки пошуку, стани «завантаження / порожньо / помилка», ширини 360–1920 px у кількох браузерах, Lighthouse, клавіатура й контраст, чистий клон за README. Знайдене під час ручної перевірки (смикання стрілки випадного списку, подвійна рамка в пошуку на головній, закріплена панель фільтрів) виправив AI за вказівкою; вручну код проєкту не редагувався. Повний чек-лист — у [`docs/AI_LOG.md`](docs/AI_LOG.md#ручна-перевірка-людиною).

## Як запустити

Потрібен Node.js 20+. Залежностей немає.

```bash
npm run dev
```

Команда збирає сайт у `dist/` (~80 запитів до API, ~20 с; локально відповіді кешуються на 6 год у `.cache/`) і запускає сервер на http://localhost:8080 з тими самими правилами, що й Netlify: та сама функція-проксі `/api/fs`, сторінки сайтів, 404 і заголовки з `netlify.toml`.

Окремо: `npm run build` — лише збірка, `npm run serve` — лише сервер, `npm run og` — перемалювати картинки превью з `scripts/og.html` (потрібен локальний Chrome; готові PNG лежать у `src/static/`).

**Деплой (Netlify):** репозиторій підключено до Netlify, кожен push у `main` збирається автоматично. Налаштування — у `netlify.toml`: команда `npm run build`, папка `dist`, Node 22, функція `netlify/functions/fs.mjs`, заголовки безпеки та кешу.

### Структура
```
src/js/config.js      задачі, ніші, фільтри, стоп-лист
src/js/api.js         клієнт FreeSerp (браузер → /api/fs, Node → напряму)
src/js/classify.js    евристика ціни / доступу з доказами
src/js/listing.js     стан фільтрів ↔ URL ↔ параметри API
src/js/templates.js   HTML-шаблони (спільні для збірки та браузера)
src/js/query.js       запит → задача чи ніша (словники основ uk / en)
src/js/i18n.js        словники uk / en
src/js/app.js         браузер: фільтри, порівняння, картка сайту
src/css/style.css     стилі
scripts/build.mjs     генерація статичних сторінок, sitemap, robots
scripts/serve.mjs     локальний сервер із правилами Netlify
scripts/og.html, og.mjs  макет картинки превью (og:image) і рендер у PNG через headless Chrome
netlify/functions/fs.mjs  проксі до FreeSerp зі списком дозволених параметрів
```

## Що не встигли

- Статичні сторінки оновлюються лише під час збірки. Щоденну перезбірку (Netlify build hook + cron) не налаштовано, хоча фільтри завжди беруть свіжі дані з API.
- Фільтр ціни/доступу перевіряє лише перші ~100–200 результатів (запит із підказкою «free» / «no sign up» плюс звичайний): API так не фільтрує, тому класифікація відбувається на нашому проксі за текстом сторінки. Це чесно написано біля результатів. У деяких задачах (лого, брендинг) фраза «без реєстрації» трапляється на сторінках дуже рідко, тож збігів може бути 0–1.
- Евристика ціни дає приблизно 2/3 точних позначок, у решти випадків — частково вірні або «не визначено» (див. перевірку на 24 сервісах у `docs/API_NOTES.md`). На ~780 зібраних сайтах ціну не визначено в 37% випадків, доступ — у 46%; «без реєстрації» прямо написано лише на ~4% сторінок.
- Фільтр «не продукт» і позначка «Не офіційний сайт» — теж евристики: блоги й огляди без явних формулювань лишаються у списках, а список брендів (18) ведеться вручну.
- Описи сайтів англійською — так їх генерує API; машинного перекладу немає.
- Автотестів немає, перевірка — ручна в браузері (десктоп і мобільна ширина).

## Що доробили б далі

1. Щоденна перезбірка та знімки даних у БД (MySQL), щоб показувати тренди ніш і конструкторів: в API немає історії.
2. Точніше визначення ціни: окремо завантажувати сторінку `/pricing` через `index=web` і кешувати результат класифікації на сервері (Netlify Function).
3. Збирати відгуки користувачів про позначки («ціна вказана невірно») для калібрування евристики.
4. Скріншоти сайтів, вибране, порівняння більше ніж 3 сайтів.
5. Сторінки «найкращі безкоштовні інструменти для X» як окремі SEO-посадкові.
