# AI Radar — правила проєкту для AI-асистента

Каталог нових AI-сайтів на FreeSerp API. Тестове завдання Semalt.

## Стек і межі
- Лише HTML, CSS, ванільний JS (ES-модулі). Жодних фреймворків, бандлерів і npm-залежностей.
- `src/js/*` — ізоморфні модулі: їх імпортує і браузер, і `scripts/build.mjs` (Node 20+). Не використовувати там `window`/`document` поза `app.js`.
- Збірка: `npm run build` → `dist/`. Локально: `npm run dev` (збірка + сервер на :8080 з правилами як у `netlify.toml`).

## API
- Перед зміною запитів читати `docs/API_NOTES.md` — там перевірені обмеження. Не вигадувати поля та параметри, яких немає в `https://freeserp.ai/docs.php` або `?help=1`; нове — спочатку перевірити curl-запитом.
- Браузер ходить лише через проксі `/api/fs` (FreeSerp дублює CORS-заголовок). Node ходить напряму.
- Кожен запит містить `agent` і `project` (`API_IDENTITY`). Збірка — послідовно, з паузою.

## Дані та чесність
- Ціна/доступ — евристика (`classify.js`). У UI завжди показувати докази («чому так»), не писати «потрібна реєстрація», якщо знайдено лише «log in».
- Стоп-лист NSFW/казино застосовується до всіх списків (`isBlocked`).
- `went_live` — «в індексі з», не «запущено».

## Мова та стиль
- Інтерфейс: українська (корінь) + англійська (`/en/`). Будь-який новий рядок — в обидва словники `i18n.js`.
- Дизайн: темна тема, Inter, кнопки та інпути `border-radius: 100px`, кольори — токени в `:root` (`style.css`).
- Селекти пишемо звичайним `<select class="input">` — `customSelect()` в `app.js` сам замінить його на випадний список у стилі застосунку (нативний лишається прихованим у формі).
- Екранувати всі дані API через `esc()`; зовнішні URL — через `safeUrl()`.

## Перевірка змін
- Після змін: `npm run build`, відкрити превʼю, перевірити головну, сторінку задачі з фільтрами ціни/доступу, картку сайту (і не пререндерену), порівняння, `/en/`, мобільну ширину 375px (без горизонтального скролу).
